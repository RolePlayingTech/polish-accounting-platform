# Zasady bezpieczeństwa projektu

**Status:** dokumentacja koncepcyjna — obecnie nie ma wdrożonej aplikacji, serwera MCP ani produkcyjnych systemów.

- **Nie publikuj publicznie** szczegółów luki pozwalającej na ujawnienie dokumentów, przekroczenie uprawnień, wyciek certyfikatów KSeF czy nieautoryzowane księgowanie.
- Po utworzeniu repozytorium w GitHub zaleca się włączyć **Private vulnerability reporting** w jego ustawieniach Security. Zgłoszenia kieruj tam; do czasu uruchomienia tej opcji korzystaj wyłącznie z prywatnego, uzgodnionego kanału kontaktu właściciela repozytorium (brak z góry wskazanego adresu — nie publikujemy fikcyjnych danych kontaktowych).
- Nie załączaj rzeczywistych faktur, PESEL, numerów rachunków połączonych z tożsamością, tokenów, prywatnych kluczy ani certyfikatów.
- Przed produkcją wymagany jest przegląd modelu zagrożeń, testy bezpieczeństwa i procedury reakcji na incydent.

Szczegółowy model ryzyk: [docs/10-bezpieczenstwo.md](docs/10-bezpieczenstwo.md).
