## 1. Definicje poziomów dojrzałości (`status`)

Każdy rekord w rejestrze ocenia dojrzałość **end-to-end** dla wskazanego profilu prawnego i okresu (`2025` / `2026`), a nie samą obecność formularza UI lub funkcji pomocniczej:

| Status         | Kryterium techniczne i merytoryczne                                                                                                                                                                                                                                                                                                                           | Dopuszczalna ekspozycja w produkcie                                                                         |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `verified`     | Przepływ `UI + REST + MCP` (gdzie dotyczy) utrwalany w PostgreSQL 18.6 pod `FORCE RLS`, potwierdzony po zimnym restarcie, walidowany oficjalnym XSD (dla e-faktur/JPK), bez otwartych defektów P0/P1 oraz **z udokumentowanym odbiorem księgowej / doradcy podatkowego** na zestawach referencyjnych.                                                         | Pełne wsparcie dla wskazanego profilu i roku (po spełnieniu bramki środowiska `#100`).                      |
| `implemented`  | Kompletny pionowy wycinek działa deterministycznie w kodzie (`UI + REST + MCP + PG18.6`) i przeszedł automatyczne testy jednostkowe, integracyjne, kontrprzykładowe i E2E na dwumiesięcznych zestawach referencyjnych (`GLD-01..GLD-14`), lecz **oczekuje na zewnętrzny odbiór merytoryczny księgowej/doradcy** (lub poświadczenia zewnętrznego sandboxu MF). | Dostępny w syntetycznym pilocie z jawnym oznaczeniem braku formalnego odbioru doradcy podatkowego.          |
| `experimental` | Wybrany wycinek funkcjonalny działa w kontrolowanym zakresie syntetycznym (np. konsultacje `#121` Etap B przez REST/MCP bez docelowego portalu `/accounting`, albo adapter KSeF 2.0 bez uwierzytelnionego tokenu zewnętrznego MF).                                                                                                                            | Wyłącznie środowisko rozwojowe / pilot syntetyczny z widocznym oznaczeniem ograniczeń (`NOT RUN` / zakres). |
| `planned`      | Zdefiniowany kontrakt architektoniczny / ADR / horyzont (`H1–H3`), brak zweryfikowanego przepływu wykonawczego end-to-end.                                                                                                                                                                                                                                    | Ukryty za serwerową flagą capability lub oznaczony jako niedostępny (zero pozornych przycisków CTA).        |
| `unsupported`  | Świadomie wyłączony w bieżącym zakresie dla danego profilu prawnego lub reżimu (np. zapis KPiR w spółce z o.o. albo stawka `2%` najmu prywatnego w `JPK_EWP(4)`).                                                                                                                                                                                             | Twarda odmowa po stronie API/domeny (`400`/`403`/`422`) z czytelnym komunikatem po polsku.                  |

## 3. Wersjonowany rejestr i stan weryfikacji źródeł urzędowych oraz schem XSD (`#4`, `#82`, `#98`)

```text
sourceId:               unikalny identyfikator reguły lub schemy (np. JPK_V7M_V3_2026, KSEF_FA3_XSD)
category:               tax_rule | xsd_schema | openapi_contract
officialSourceUrl:      bezpośredni link do ISAP / Dz.U. / M.P. / podatki.gov.pl / CRD / CIRFMF
actOrSchemaReference:   pozycja Dz.U./M.P. + artykuł LUB przestrzeń nazw targetNamespace + wersja wzoru
effectiveFrom / To:     przedział obowiązywania wg daty zdarzenia / okresu (YYYY-MM-DD)
pinnedArtifactSha256:   suma SHA-256 przypiętego pliku .xsd / .json w test/fixtures/xsd/manifest.json
applicableProfiles:     lista profili (np. [JDG_KPIR, JDG_RYCZALT, SPZOO_UOR])
goldenFixtures:         ścieżki do testów pozytywnych i negatywnych (w tym XXE, błędny NIP, granica dat)
verificationStatus:     verified | requires_expert_review | unverified (fail-closed)
expertReviewStatus:     PENDING | APPROVED (<data>, <zakres>, <recenzent merytoryczny>)
```
